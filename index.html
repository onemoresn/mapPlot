    Welcome to MapPlot

    MapPlot displays your team's locations on a live interactive map. As the host, you share a link — your team types their location and they appear on the map instantly.

    You'll need a free Google account to set up the Firebase backend. This wizard takes about 5 minutes.

    Step 1 — Create a Firebase Project

    1. Open console.firebase.google.com and sign in
    2. Click Add project and give it any name
    3. Disable Google Analytics (not needed) and click Create project
    4. From the Project Overview, click the </> Web icon to register a web app
    5. Enter a nickname, click Register app
    6. Keep the firebaseConfig values visible — you'll paste them in Step 3

    Step 2 — Enable Realtime Database

    1. In the Firebase Console left menu, click Build → Realtime Database
    2. Click Create Database
    3. Choose a region and click Next
    4. Select Start in test mode, then click Enable
    5. Copy the Database URL shown at the top of the page:
      https://your-app-default-rtdb.firebaseio.com

    ⚠ Test mode rules expire after 30 days, after which all reads and writes are blocked. For a permanent deployment, go to Realtime Database → Rules in the Firebase Console and set both .read and .write to true, then click Publish.

    Step 3 — Paste Your Firebase Config

    Copy the values from your Firebase project's web app config object.

    📖 User Guide

    Overview

    MapPlot lets you collect real-time location pins from multiple people and display them on a shared interactive map. There are two roles:

    • Host — sets up Firebase, runs the map, and shares the user link.
    • User — opens the shared link and submits their location.

    All data is stored in your own Firebase Realtime Database. Nothing passes through any third-party server.

    For Hosts

    First-time setup

    1. On first launch the Setup Wizard opens automatically. Follow the steps to connect a free Firebase project.
    2. To edit your configuration later, click ⚙ Settings. To re-run the wizard, click Setup Wizard inside Settings.

    The map view

    • The sidebar lists every pinned location, sorted by number of people.
    • Click any entry to fly the map to that location and open its popup.
    • The status dot pulses green when syncing live, or yellow while connecting.

    Sharing with users

    1. Click Copy User Link in the sidebar.
    2. Share the copied URL via chat, email, or QR code.
    3. Recipients open the link on any device — no install needed.

    The user link embeds your Firebase config. Do not share it publicly if your database rules are open.

    Resetting the map

    Click Reset Map to delete all pins for everyone. This cannot be undone.

    For Users

    1. Open the link shared by your host.
    2. Type your location — a city, region, country, or postal code.
    3. Click Pin My Location or press Enter.

    Your pin appears on the host's map within seconds. Submitting again moves your existing pin — no duplicate is created.

    Location is stored per-device. Clearing your browser or app data will remove your pin.

    Troubleshooting

    Location not found
    Try a broader term — use a city or country instead of a full street address.
    Map not updating / yellow dot
    Check your Firebase config in ⚙ Settings. Make sure the Database URL is correct and Realtime Database is enabled. Also check your database rules — if .read is not set to true, the host map cannot receive live updates. In the Firebase Console go to Realtime Database → Rules and confirm both .read and .write are true.
    Pins not saving (permission denied)
    In the Firebase Console, go to Realtime Database → Rules and confirm both .read and .write are set to true (or appropriately scoped). Without .write: true users cannot save pins; without .read: true the host map cannot load them.
    User link says "missing configuration"
    Re-copy the user link from the sidebar after saving your config — the link automatically embeds the config.
    Firebase test mode expired
    When you create a Realtime Database in test mode, Firebase automatically sets the rules to expire after 30 days. After expiry, all reads and writes are blocked — the host map stops updating and users cannot save pins. To fix it, go to Realtime Database → Rules in the Firebase Console and replace the rules with:
    { "rules": { ".read": true, ".write": true } }
    Then click Publish. This re-enables full access with no expiry.
